# PDF Datei Umbenenner

Приложение переименовывает школьные PDF-формуляры по каноническому имени ученика, предмету и явно выбранным месяцу и году. Основной интерфейс написан на Tkinter; CLI использует тот же сервис обработки.

## Что поддерживается

- старый формуляр с именем и предметом в верхней части страницы;
- новый `Anwesenheitsnachweis`, где имя находится над `Name des Schülers`, а предмет - в столбце `Fach`;
- PDF с текстовым слоем без установки OCR;
- опциональный OCR первой страницы для печатного текста;
- ручное подтверждение неизвестного ученика и запоминание OCR-варианта как алиаса;
- безопасный импорт и редактирование `Schuler.csv`;
- коллизии имён на диске и внутри одного пакетного запуска.

Тип формуляра определяется по структуре и надписям страницы, а не по исходному имени PDF. Данные преподавателя используются только как структурная граница формуляра и никогда не входят в итоговое имя. `Lehrer.csv` в переименовании не участвует.

## Итоговое имя файла

Формат всегда один:

```text
Nachname_Vorname_Fach_Monat_Jahr.pdf
```

Обезличенный пример:

```text
Beispiel_Lena_Mathematik_April_2028.pdf
```

Месяц записывается по-немецки. Месяц и год берутся только из значений, выбранных перед запуском GUI, либо из обязательных параметров CLI. Даты внутри формуляра и системная дата на итоговое имя не влияют.

При коллизии выбирается первый свободный суффикс без перезаписи существующих файлов:

```text
Beispiel_Lena_Mathematik_April_2028.pdf
Beispiel_Lena_Mathematik_April_2028_1.pdf
Beispiel_Lena_Mathematik_April_2028_2.pdf
```

## Установка и запуск в Windows

Требуется Python 3.10 или новее с `tkinter`.

### Первичная установка

Запустите:

```cmd
setup.bat
```

Скрипт создаёт локальное `.venv`, устанавливает обязательные зависимости и выполняет core health-check. Установка OCR предлагается отдельно; отказ не мешает работе с обычными PDF. Системные компоненты не устанавливаются молча и повышение прав не запрашивается.

### Обычный запуск

```cmd
start_app.bat
```

Это основной ежедневный запуск. Он использует только `.venv`, проверяет состояние обязательных зависимостей и ремонтирует окружение лишь при проблеме Python-модулей или изменении `requirements.txt`. Ошибки `subjects_config.json` и `Schuler.csv` показываются как ошибки данных и не запускают бессмысленную переустановку пакетов. Диагностика сохраняется в `.launcher-logs\start_app.log`.

Проверка лаунчера без открытия GUI:

```cmd
start_app.bat --health-only
```

### Быстрый запуск

```cmd
quick_start.bat
```

`quick_start.bat` только запускает уже готовое `.venv`: он не устанавливает и не ремонтирует пакеты. Если окружения нет, используйте `start_app.bat`.

## Работа в GUI

На вкладке `Verarbeitung`:

1. выберите входной каталог;
2. выберите `Monat` и `Jahr`;
3. при необходимости включите `Testmodus (keine Änderungen)`;
4. нажмите `Verarbeitung starten`.

Настройки фиксируются в начале пакета. Во время обработки каталог, период и операции изменения справочника блокируются. Кнопка `Stoppen` завершает текущий PDF и останавливается между файлами. Закрытие окна во время пакета предлагает такое же безопасное завершение.

Dry-run возвращает полный план, но не перемещает PDF, не изменяет `Schuler.csv`/алиасы и не сохраняет `manual_review.json`.

## Неизвестный ученик и вкладка `Prüfung`

Если точного совпадения с `Schuler.csv` или подтверждённым алиасом нет, PDF направляется в `manual_check`, а запись атомарно сохраняется в `manual_review.json`. Если очередь сохранить невозможно, приложение пытается вернуть PDF на исходное место и показывает явную ошибку.

На вкладке `Prüfung` доступны три явных решения:

- выбрать существующего ученика и при необходимости сохранить распознанное написание как алиас;
- исправить имя, добавить нового ученика и применить переименование;
- только переименовать PDF без изменения справочника после отдельного подтверждения.

После добавления нового ученика или сохранения алиаса следующее такое же распознавание находится автоматически. Поэтому неизвестного ученика обычно требуется подтвердить один раз.

Неизвестный предмет, конфликтующие значения в столбце `Fach` и несколько разных предметов вопреки контракту также требуют ручной проверки. Исправленный вариант предмета может быть сохранён в `subjects_aliases.json`.

## Справочник `Schuler.csv`

Вкладка `Schüler` позволяет:

- искать и фильтровать записи;
- создавать и редактировать ученика;
- активировать или деактивировать запись без физического удаления истории;
- просматривать и удалять ошибочные алиасы;
- искать потенциальные дубликаты;
- импортировать обновлённый CSV.

Поддерживаются UTF-8/UTF-8 BOM, заголовки `Vorname` и исторический `Forname`, а также `;`, `,`, табуляция и `|` при импорте. Перед применением показывается diff:

- новые записи;
- неизменённые записи;
- конфликты номеров или имён;
- дубликаты;
- записи, отсутствующие в новом файле.

Применение требует явного подтверждения. Добавляются только новые бесконфликтные строки; конфликты и дубликаты не перезаписываются, отсутствующие исторические записи не удаляются. Перед массовым изменением создаётся `Schuler.csv.bak` (при повторении - следующий свободный суффикс), а итоговый CSV заменяется атомарно. Matcher обновляется без перезапуска приложения.

Минимальные поддерживаемые колонки:

```csv
Nummer;Nachname;Vorname
1;Beispiel;Lena
```

Опциональная колонка `Aktiv` принимает логические значения, поддерживаемые приложением.

## Опциональный OCR

OCR запускается только для PDF без достаточного текстового слоя. Для него нужны:

- Python-зависимость из `requirements-ocr.txt` (`PyMuPDF` для рендера первой страницы);
- отдельно установленный Tesseract;
- языковые данные `deu` и `eng`.

Проверка:

```cmd
.venv\Scripts\python.exe bootstrap.py check-ocr
```

При недоступном OCR PDF с текстовым слоем продолжают обрабатываться. PDF без текста направляется на ручную проверку с диагностикой. OCR рассчитан на печатные поля; надёжное чтение рукописного текста не обещается. Низкая уверенность имени или предмета запрещает автоматическое переименование.

## Резервные копии и восстановление

CSV и JSON приложения записываются через временный файл, `fsync` и атомарную замену. Повреждённые `manual_review.json` и файлы алиасов открываются в fail-closed режиме: приложение сообщает ошибку и не перезаписывает исходный файл как пустой.

Перед ручным восстановлением:

1. закройте приложение;
2. скопируйте повреждённый файл и каталог `manual_check` в резервное место;
3. сопоставьте каждый PDF с записью очереди;
4. только после этого исправьте JSON либо создайте новую пустую очередь `{"review_items": []}`.

Если локальное окружение повреждено, закройте приложение, удалите только каталог `.venv` внутри проекта и снова запустите `setup.bat` или `start_app.bat`. Пользовательские PDF, CSV и JSON при этом не удаляются.

## CLI

CLI требует явных месяца и года:

```cmd
.venv\Scripts\python.exe main.py C:\PDF-Eingang --month 4 --year 2028
```

Безопасный dry-run:

```cmd
.venv\Scripts\python.exe main.py C:\PDF-Eingang --month 4 --year 2028 --dry-run
```

При ошибке отдельного PDF пакет продолжает работу. Ошибки обработки или сохранения очереди дают ненулевой код возврата, чтобы автоматизация и BAT-файлы не считали такой запуск успешным.

## Health-check и тесты

```cmd
.venv\Scripts\python.exe bootstrap.py check-core
.venv\Scripts\python.exe bootstrap.py check-ocr
.venv\Scripts\python.exe -m pytest
```

Core не зависит от OCR. Реальный OCR-тест автоматически пропускается, если Tesseract, PyMuPDF или нужные языковые данные отсутствуют.

## Данные и Git

`Schuler.csv`, `Lehrer.csv`, `manual_review.json`, `subjects_aliases.json` и PDF в `scans` могут содержать персональные или операционные данные. Не используйте реальные данные в примерах, публичных issue и тестовых фикстурах.

В текущем репозитории эти пользовательские файлы и образцы уже отслеживаются Git. Финальный QA не меняет это решение без отдельного согласования. `.gitignore` не удаляет уже отслеживаемые файлы и не очищает историю, поэтому перед публикацией репозитория необходимо отдельно оценить содержимое и историю Git.

## Основные файлы

- `processing_service.py` - единая бизнес-логика обработки документа;
- `gui_main.py` - основной GUI;
- `gui_minimal.py` - совместимый тонкий запускатель того же GUI;
- `main.py` - CLI-адаптер;
- `form_parser.py` - определение и парсинг двух формуляров;
- `student_registry.py` и `student_registry_service.py` - сопоставление, CRUD и импорт учеников;
- `review_actions.py` и `review_queue.py` - ручное подтверждение и durable queue;
- `ocr.py` и `pdf_extractor.py` - текстовый слой и OCR fallback;
- `bootstrap.py` и BAT-файлы - окружение и запуск.
